==================================================
88. STRICT PUBLIC-PAGE CONTENT PURITY RULE
==================================================

ABSOLUTE RULE:

NO AI-FACING, SYSTEM-FACING, EDITORIAL-PROCESS, TECHNICAL, EXPLANATORY, ADMINISTRATIVE OR META-COMMENTARY TEXT MAY APPEAR ON NORMAL PUBLIC SITE PAGES.

Public pages must contain only the actual intended site content and the minimum interface text necessary to navigate it.

The public site must NEVER display wording such as:

- AI-generated
- generated by AI
- AI summary
- AI interpretation
- AI commentary
- machine-generated
- automated note
- system note
- editorial note
- processing note
- source-processing note
- OCR note
- confidence note
- verification note
- provenance class
- internal classification
- generated content class
- restoration status
- review status
- ingestion status
- draft status
- model commentary
- assistant commentary
- explanation of how the text was produced
- technical implementation comments
- debugging text
- placeholder explanations
- internal instructions
- moderation text
- system prompts
- developer prompts
- pipeline messages
- content-generation explanations
- administrative warnings
- internal IDs unless bibliographically necessary
- raw database labels
- raw JSON keys
- source-processing diagnostics.

Such information, when required for governance or audit, belongs ONLY in:

- admin interfaces;
- internal metadata;
- research audit records;
- provenance databases;
- logs;
- private quality-control views.

It must not contaminate the normal reader-facing experience.


==================================================
89. ALLOWED PUBLIC TEXT TYPES
==================================================

Normal public pages may display only meaningful reader-facing content such as:

- page titles;
- section titles;
- subtitles;
- navigation labels;
- concise functional interface labels;
- extracted source text;
- verified quotations;
- source-grounded articles;
- generated story/editorial content permitted by this master instruction;
- Qur'anic verses;
- hadith;
- sayings attributed to the Prophet ﷺ;
- Seerah passages;
- sayings of companions;
- sayings of tabiʿin;
- sayings of atbaʿ al-tabiʿin;
- sayings and transmitted teachings of the major saints, masters, scholars and figures included in the approved site corpus;
- hikam;
- aphorisms;
- prayers;
- invocations;
- poems or praise material where properly included;
- historical narratives;
- biographies;
- stories;
- research-derived prose;
- explanatory content genuinely intended for the reader;
- bibliographic citations;
- source references;
- dates, names and factual metadata relevant to the subject.

Every visible block must serve the reader's subject-matter experience.

If text exists only to explain the site's internal production process, it must not appear publicly.


==================================================
90. NO AI COMMENTARY AROUND CONTENT
==================================================

Do not prepend or append AI commentary to articles, stories, quotations or extracted passages.

Forbidden public patterns include:

"AI summary:"
"Here is a generated explanation:"
"This content was produced automatically:"
"The following passage was reconstructed by AI:"
"AI interpretation:"
"Our system found:"
"This article was generated from..."
"This story is unsourced/generated:"
"Confidence: 92%"
"OCR repaired automatically"
"Source verification passed"
"Generated on..."
"Model note:"
"Editorial pipeline note:"

The reader should encounter the content itself, not commentary about its production mechanism.


==================================================
91. INTERNAL PROVENANCE MUST REMAIN INVISIBLE BY DEFAULT
==================================================

The internal distinction between:

- SOURCED_EXTRACTED;
- SOURCE_GROUNDED_SYNTHESIS;
- LEGACY_UNSOURCED_STORY;
- GENERATED_UNSOURCED_STORY;
- REVIEW_REQUIRED;

must remain available to the system for governance.

However, these raw internal labels must NOT appear on ordinary public pages.

The distinction may affect:

- citation behavior;
- publication eligibility;
- internal search;
- audit reports;
- admin views;
- quality-control systems.

It must not result in technical labels appearing beside normal reader-facing content.


==================================================
92. SOURCE DISPLAY WITHOUT PIPELINE COMMENTARY
==================================================

Where source information is appropriate, display it in normal scholarly form only.

Allowed examples:

- اسم الكتاب
- اسم المؤلف
- الجزء
- الصفحة
- الراوي
- التخريج
- المرجع
- المصدر
- edition/publisher details where relevant

Do NOT display:

- extraction engine;
- OCR engine;
- AI model;
- parsing method;
- ingestion batch;
- confidence score;
- pipeline state;
- internal restoration path;
- source-class enum.

Public citations must look like citations, not system diagnostics.


==================================================
93. GENERATED CONTENT PUBLIC-PRESENTATION RULE
==================================================

Where generated editorial/story content is permitted under this master instruction, present it as normal site content.

Do not surround it with AI disclaimers, technical notices or model commentary.

However:

- never attach a false historical source;
- never represent invented dialogue as a documented quotation;
- never label generated prose as verbatim extraction;
- never place it inside quotation marks in a way that falsely implies historical transmission.

Internal provenance must remain recorded even when it is not printed on the ordinary page.


==================================================
94. QUOTATION PURITY RULE
==================================================

Quotation blocks must contain only:

- the genuine quotation;
- speaker attribution where required by this master instruction;
- concise source citation where appropriate.

Do not place commentary such as:

- "AI explanation";
- "editor's generated reflection";
- "system interpretation";
- "automatically selected";
- "recommended by AI";

inside or adjacent to the quotation block unless the page is explicitly an administrative/research tool rather than a normal public reading page.


==================================================
95. QUR'AN AND HADITH DISPLAY PURITY
==================================================

Qur'anic verses and hadith must be presented with particular textual discipline.

A Qur'anic display may contain:

- verse text;
- surah name;
- verse number;
- translation where applicable;
- accepted explanatory/source material in the appropriate page context.

A hadith display may contain:

- hadith text;
- narrator;
- source;
- reference;
- translation;
- relevant scholarly explanatory content.

Do not intermingle AI/system remarks within the sacred/source text presentation.


==================================================
96. HIKAM, SAINTS' SAYINGS AND MASTER TEACHINGS
==================================================

For hikam, sayings, spiritual teachings and quotations from recognized masters/saints/scholars included in the approved corpus:

display only:

- the saying itself;
- attribution according to the site's attribution policy;
- source where appropriate;
- genuine reader-facing explanation if the page calls for it.

Never add invisible-source-looking AI sayings to the quotation corpus.

Generated reflections must remain editorial prose and must never be visually represented as transmitted hikam or historical quotations.


==================================================
97. PUBLIC-PAGE CLEANLINESS FILTER
==================================================

Before publishing or rebuilding any public page, run a cleanliness check for prohibited meta-language.

Detect and remove or block public rendering of terms/patterns related to:

- AI generation;
- system messages;
- internal status;
- confidence;
- OCR diagnostics;
- extraction diagnostics;
- debugging;
- TODOs;
- placeholders;
- pipeline steps;
- admin instructions;
- raw provenance enums;

This filter must apply to:

- HTML;
- JSON-fed public rendering;
- biographies;
- articles;
- children pages;
- quotations;
- reader interfaces;
- media pages;
- resource pages;
- search results;
- error/fallback content.


==================================================
98. NO PLACEHOLDER OR DEVELOPMENT COMMENTARY
==================================================

Never expose public text such as:

- Coming soon
- Placeholder
- Sample text
- Demo content
- TODO
- Needs review
- Pending AI generation
- Waiting for OCR

- Test article

Even then, keep the message concise and neutral.

Do not expose internal development status as content.

==================================================

Interface text should be concise and functional.

Permitted examples:

- التالي

- المصادر
- المراجع

Avoid verbose interface explanations when the UI can communicate the action clearly.

The site should feel like a finished digital publication, not a software-development dashboard.


==================================================
100. ADMIN / RESEARCH EXCEPTION
==================================================

The prohibition on technical/meta text applies to NORMAL PUBLIC PAGES.

Dedicated private or research-oriented audit interfaces may expose:

- OCR repair records;
- source witnesses;
- confidence;
- provenance class;
- restoration history;
- ingestion status;
- duplicate analysis;
- publication status;
- AI-assisted processing metadata.

Such interfaces must be clearly separated from the ordinary public reading experience.

No public article, biography, child page, quotation page or media page should accidentally inherit these diagnostics.

==================================================

Before publication ask:

"Is every visible sentence here either:

1. actual subject-matter content,
2. a title/subtitle,
3. a genuine quotation/source passage,
4. a citation/reference,

remove the extraneous text from the public rendering.
